2026-08-04 · Phase 00 close. **`NEXT_PUBLIC_SUPABASE_ANON_KEY` in `.env.local` held the `sb_secret_` key**, which bypasses RLS — confirmed by SHA-256 against `supabase status`, not by eyeballing the prefix · config + tests · swapped to the publishable key; `scripts/assert-build-safe.mjs` now fails the build if secret-shaped material reaches `.next/static`. Two things make this worse than a typo: any `pnpm build` would have inlined a service-role key into a public JS chunk, and *locally the app was running with RLS entirely inert* while `test:rls` went green — because the suite reads its keys from `supabase status` and the app reads `.env.local`. **The tests certified a boundary the running app was not enforcing.** Also hardened `.claude/hooks/secret-guard.sh`, whose rule matched the variable *name* (`NEXT_PUBLIC_*SECRET*`) and so sailed past a legitimate name with a secret value.

2026-08-04 · Phase 00 close. `/api/test-auth` shipped in the production route manifest, and its second gate was a lie: `NEXT_PUBLIC_SUPABASE_URL` is inlined by Next at build time, so "refuse unless Supabase is localhost" froze into a literal describing the *build machine*. Meanwhile `lib/supabase/server.ts` reads the same variable through a dynamic `process.env[name]` lookup, which is **not** inlined — so the client talked to production while the gate still asserted localhost. A build made locally and deployed with production env was a live backdoor · code + tests · renamed to `route.e2e.ts` and gated through `pageExtensions`, so it is absent from the manifest rather than guarded at runtime; verified in both directions. The general lesson: **`NEXT_PUBLIC_*` is a build-time constant, so it can never be a runtime security check** — and a security control that lives only in a comment's confidence ("gate 2 is the one that matters") is worth exactly nothing until something executes it.

2026-08-04 · Phase 00 close. Four RLS escalations, all reproduced independently before being accepted: any user could self-grant `is_pro`, insert their own `profiles` row directly (bypassing `create_profile`, choosing any slug — permanently, because the slug-immutability trigger then locks the squat in), forge `status:'accepted'` on their own `institution_requests` row, and call `claim_profile_slug` **anonymously** as a user-existence oracle · schema (PENDING APPROVAL) · root cause is one line: `grant select, insert, update on profiles to authenticated` is table-level, so the policies authorise the *row* and nothing constrains the *columns*. The anon RPC is a separate trap — Postgres grants `EXECUTE` to `PUBLIC` by default, so the explicit `grant ... to authenticated` in the migration is decorative. `tests/rls/foundation.test.ts` tests the row dimension thoroughly and the column dimension not at all, which is precisely where all four live: **33 green tests over four working escalations.**

2026-08-04 · Phase 00 close. The first version of `assert-build-safe.mjs` — written to catch the secret-key bug above — matched a hand-guessed base64 substring for the service-role JWT claim. 2026-08-04 · Phase 00 close. The design-critic calibration planted a hardcoded hex, a 13px gap and a 300ms transition — and revealed that **`lint:tokens` caught 1 of the 3**, not 3. `checkCssPixels`/`checkCssDuration` ran on `.css` files only, so `style={{ gap: '13px' }}` in a `.tsx` was unguarded, while the script's own header claimed inline styles were covered · tests + code · both checks now run on every file type; `scripts/__fixtures__/violations.tsx` carries each violation in *both* syntaxes plus one reached through a variable. Two compounding causes worth naming: `off-grid-px` and `raw-duration` were the only rules missing from `expectedRules`, and they were the only rules that were silently CSS-only — **a rule with no test is a rule that can stop matching without anyone noticing**. And the fixture's header asserted a guarantee the linter did not provide, which is the false-confidence failure `docs/MEASUREMENT.md` was written to watch for. The lesson generalises past this bug: calibrating the checker found a hole in the guarantee it was being measured against. Do the same for `lint:i18n`, `lint:contrast` and the RLS suite before trusting them.

2026-08-04 · Phase 00 close. design-critic calibration result: caught the hex (by scripting a pixel read and converting OKLCH→sRGB itself), missed the 13px gap, correctly did *not* report the 300ms transition, zero false positives · AI layer · `.claude/agents/design-critic.md` now requires per-finding provenance (pixel-verified / visual / inferred), a mandatory "what I did not check" section, and forbids asserting an absence a still image cannot show. 4px-grid conformance was removed from its remit and left to `lint:tokens`.
