# 03 Editor & Writing Surfaces

This folder demonstrates the mechanical rules for creating focused, distraction-free text editors and handling contextual popovers (like slash menus and AI assistants) without breaking the user's reading flow.

*   **Typographical Constraints (`focused_editor.png`):** The primary writing surface is not full-width; it is strictly constrained to a maximum width of roughly 700px–900px. This enforces an optimal line length of 60–80 characters for readability. Empty states and placeholders use a low-contrast, muted gray text to invite interaction without demanding visual hierarchy.
*   **Contextual Slash Menus (`notion_slash_menu.png`):** Slash command menus anchor directly to the text cursor's $X, Y$ coordinates, not the center of the screen. The menu enforces a strict max-height (approx. 300px) with an internal scrollbar. Row density is tight (28px–32px tall), pairing a left-aligned 20px–24px icon container with a flush-right keyboard shortcut hint in a reduced font weight and color.
*   **Page Options & Toolbars (`breadcrumbs_options_2.jpg`):** Floating editor menus use a fixed width (approx. 240px–260px) and anchor to the top right to avoid obscuring the main text body. Internal spacing relies on tight 4px–8px padding, with distinct functional groups divided by a single 1px hairline separator. 
*   **Side-by-Side Context (`editor_ai_chat.png`):** When introducing secondary complex tools (like an AI chat or block settings), they appear as a rigid sidebar (approx. 300px–350px wide) that mechanically reflows the main editor canvas rather than floating over it. This guarantees the user can reference their text and the tool simultaneously without overlapping z-index issues.
*   **Math & Heading Spacing (`latex_with_text.jpg`):** Inline mathematical symbols share the exact baseline as the surrounding prose. Display equations (block math) are centered and utilize substantial vertical padding (16px–24px top and bottom) to separate them from paragraph text. Heading spacing is asymmetrical: the `margin-top` above a heading is always 1.5x to 2x larger than the `margin-bottom` below it, structurally binding the heading to the text that follows it.
* **Inline AI Prompt (`editor_ask_ai.png`)**: The inline AI input field spans the primary text column, inheriting the exact max-width and margins of the surrounding prose so it feels native to the document's flow. It uses a distinct structural container—typically a 1px border with a soft, diffused drop shadow and significant corner radii (e.g., 16px)—to visually elevate it above the canvas. The prompt relies on a low-contrast placeholder text (muted gray) paired with a clear, right-aligned submit action (like an upward arrow icon) nested directly inside the input bounds.
